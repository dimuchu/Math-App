# PRD: MentalMath — Тренажёр устного счёта

---

## 1. Обзор продукта

**Название:** MentalMath

**Целевая аудитория:** взрослые пользователи — специалисты из IT, финансов, консалтинга, а также те, кто готовится к собеседованиям и хочет улучшить навыки устного счёта.

**Ключевая ценность:** быстрая, сфокусированная тренировка устного счёта с адаптивной системой, которая выявляет слабые места и целенаправленно их прокачивает.

**Платформа:** нативный iOS (Swift / SwiftUI), iPhone-first с архитектурной готовностью к iPad.

**Вайб:** минималистичный, чистый, взрослый интерфейс. Без игровой мишуры, мультяшных персонажей и лишнего визуального шума. Фокус на функциональности и ощущении «флоу».

**Язык:** английский везде. Приложение расчитано на англоговорящую аудиторию и будет выливаться на все страны в App Store.

**Приоритет:** MVP

---

## 2. Ключевая механика

### Что делает
Основной цикл взаимодействия: пользователь видит пример → решает в уме → вводит ответ → мгновенно получает следующий пример.

### Зачем
Минимизация трения между задачами создаёт состояние потока, в котором тренировка максимально эффективна.

### Как работает
- Четыре базовых операции: сложение (+), вычитание (−), умножение (×), деление (÷)
- Пример отображается крупно в центре экрана
- После ввода ответа — мгновенная обратная связь (цвет, вибрация) и переход к следующему
- Интерфейс оптимизирован для использования одной рукой

**Приоритет:** MVP

---

## 3. Адаптивное определение уровня

> Это ключевая фича продукта.

### Что делает
При первом запуске (после онбординга) пользователь проходит диагностический блок из 10–15 примеров. На основе результатов формируется персональный профиль с выявлением сильных сторон и пробелов.

### Зачем
Без диагностики приложение не отличается от калькулятора с примерами. Адаптивность — главная причина, по которой пользователь выберет MentalMath.

### Как работает

1. **Диагностический блок:**
   - Перед стартом — краткое сообщение: *«Сейчас решишь несколько примеров, и мы определим твой уровень»*
   - 10–15 примеров, от простых к сложным
   - Покрывает все 4 операции и разные диапазоны чисел (1-значные, 2-значные, 3-значные)
   - Замеряется правильность и время ответа

2. **Формирование профиля:**
   - Для каждой комбинации «операция + диапазон» рассчитывается уровень владения
   - Выявляются «области некомпетентности» — операции и диапазоны, где пользователь ошибается или тратит много времени

3. **Обратная связь после диагностики:**
   - Краткая выжимка: *«У тебя пробелы в умножении 2-значных чисел и делении»*
   - Показ сильных сторон для мотивации

4. **Адаптивная сложность:**
   - Генератор задач строит тренировки вокруг выявленных пробелов
   - Чаще даёт задачи из слабых областей, реже — из сильных
   - Уровень пересчитывается по мере тренировок
   - При улучшении — постепенное повышение сложности

**Приоритет:** MVP (диагностика + базовая адаптивность), Post-MVP (тонкая настройка алгоритма)

## 4. Онбординг

### Что делает
2–3 лаконичных экрана при первом запуске, знакомящих пользователя с приложением и переводящих к диагностике.

### Зачем
Быстро объяснить ценность приложения и плавно подвести к определению уровня.

### Как работает

1. **Экран 1:** Что делает приложение — тренировка устного счёта, фокус на скорости и концентрации
2. **Экран 2:** *«Сейчас определим твой уровень»* → кнопка перехода к диагностике
3. **Экран 3 (после диагностики):** Результат диагностики + объяснение двух режимов тренировки

- Онбординг можно пропустить в любой момент
- При пропуске назначается средний уровень по умолчанию
- Онбординг показывается только при первом запуске

**Приоритет:** MVP

## 5. Режимы тренировки

Два режима, архитектурно готовых к расширению через протоколы.

### 5.1 Practice (Практика)

**Что делает:** тренировка с фиксированным количеством задач без жёсткого ограничения по времени.

**Зачем:** для вдумчивой тренировки, когда пользователь хочет прокачать конкретные навыки.

**Как работает:**
- Выбор количества задач: 5, 10, 15 и тд. задач - ползунком можно выбрать количество задач с шагом 5
- Генератор учитывает профиль пользователя — больше задач из слабых областей
- По завершении — экран результатов:
  - Решено / ошибки
  - Среднее время на задачу
  - Процент правильных ответов
  - Распределение по операциям

**Приоритет:** MVP

### 5.2 Time Attack

**Что делает:** сессия на фиксированное время с целью решить максимум задач.

**Зачем:** для тренировки скорости и работы под давлением.

**Как работает:**
- Выбор длительности: 10, 20, 30 и тд секунд - ползунком можно выбрать количество секунд до 5 мин. максимум с шагом 10 сек.
- Таймер на экране, обратный отсчёт
- По завершении — экран результатов:
  - Количество решённых задач
  - Процент правильных
  - Лучший стрик (серия правильных подряд)
  - Сравнение с личным рекордом

**Приоритет:** MVP

## 6. Вовлекающие механики (Retention)

### 6.1 Стрики (Streak)

**Что делает:** счётчик дней подряд, когда пользователь тренировался.

**Зачем:** мотивация не прерывать серию — один из сильнейших механизмов возвращения.

**Как работает:**
- Визуально заметен на главном экране
- Считается по календарным дням
- При пропуске — сброс с возможностью «спасения» (Post-MVP)

**Приоритет:** MVP

### 6.2 Личные рекорды

**Что делает:** сохранение лучшего результата в каждом режиме.

**Зачем:** соревнование с самим собой — мотивация улучшать показатели.

**Как работает:**
- Рекорды по каждому режиму и конфигурации (количество задач / время)
- Визуальное выделение при побитии рекорда (анимация, звук)

**Приоритет:** MVP

### 6.3 Прогресс по областям

**Что делает:** визуализация того, как закрываются выявленные пробелы. 

**Зачем:** показать пользователю, что тренировки работают.
**Нюанс:** Что представляет собой оценка прогресса? Как эта оценка прогресса работает? Нужно копнуть в эту механику подробнее. 

**Как работает:**
- Наглядная шкала или диаграмма по каждой операции и диапазону
- Сравнение текущего уровня с начальным (после диагностики)

**Приоритет:** MVP (базовый вид), Post-MVP (детальная визуализация)

### 6.4 Daily Challenge (Ежедневный вызов)

**Что делает:** одна короткая сессия в день с особыми условиями.

**Зачем:** дополнительная точка входа — причина зайти в приложение каждый день.

**Как работает:**
- Особые условия: только одна операция, или все операции с 3-значными числами, и т.п.
- Результат можно сравнить с «вчера»
- Доступен один раз в день

**Приоритет:** Post-MVP (Pro)

### 6.5 Push-уведомления

**Что делает:** мягкие напоминания, если пользователь не заходил 1–2 дня.

**Зачем:** вернуть пользователя в приложение.

**Как работает:**
- Настраиваемое время отправки
- Тексты мотивирующие, не навязчивые
- Полностью отключаемые в настройках

**Приоритет:** Post-MVP

## 7. UI/UX

### 7.1 Экран тренировки

**Что делает:** основной рабочий экран, где пользователь решает примеры.

**Как работает:**
- **Верх:** счёт (решено / ошибки) + таймер (если Time Attack)
- **Центр:** крупный пример (операнды и знак операции)
- **Низ:** поле ввода + цифровая клавиатура

### 7.2 Обратная связь

- **Правильный ответ:** лёгкая зелёная подсветка → мгновенный переход к следующему примеру
- **Ошибка:** короткая красная подсветка + вибрация + показ правильного ответа (~1 сек). Без поп-апов и модальных окон

### 7.3 Одноручное использование

- Все интерактивные элементы в нижней половине экрана
- Цифровая клавиатура кастомная, оптимизированная под устный счёт (крупные кнопки)

### 7.4 Анимации

- Микро-анимации для ощущения «флоу»
- Лёгкое появление примера (fade/slide)
- Плавное обновление счёта
- Анимация при побитии рекорда

### 7.5 Темы и типографика

- Светлая и тёмная тема + следование системной настройке
- Системные шрифты (SF Pro)
- Упор на читаемость и контраст

**Приоритет:** MVP (базовый UI, обратная связь, одноручное использование), Post-MVP (продвинутые анимации, полировка)

## 8. Экран статистики

### Что делает
Показывает пользователю полную картину его прогресса и результатов.

### Зачем
Визуальный прогресс — мотивация продолжать тренировки.

### Как работает

**Ключевые метрики (крупно):**
- Общее количество решённых задач
- Средний процент правильных ответов
- Текущий стрик

**Детальная информация:**
- История сессий (дата, режим, сложность, результат)
- Лучшие результаты по режимам
- Среднее время ответа
- Распределение по операциям (где сильнее, где слабее)
- Прогресс закрытия «пробелов»

**Подача:** минималистичная — пара ключевых метрик крупно, остальное — список/таблица.

**Приоритет:** MVP (базовые метрики, история сессий), Post-MVP (детальная аналитика, графики)

## 10. Монетизация (Freemium)

### Что делает
Модель freemium с разовой покупкой Pro-версии.

### Зачем
Монетизация без подписки снижает барьер входа и повышает доверие.

### Как работает

**Бесплатная версия:**
- Все 4 операции
- Один базовый уровень сложности (1–2 цифры)
- Оба режима тренировки (Practice, Time Attack)
- Ограниченная статистика (последние 10 сессий)
- Стрики и личные рекорды

**Pro (one-time unlock, lifetime):**
- Все уровни сложности (до 4–5 цифр)
- Полная статистика без ограничений
- Расширенные настройки
- Daily Challenge
- Детальная аналитика по операциям

**Paywall:**
- Аккуратный экран с описанием преимуществ Pro
- Без агрессивных тактик
- Реализация через StoreKit 2

**Архитектура:** готова к добавлению подписочной модели в будущем, но на старте — только разовая покупка.

**Приоритет:** Post-MVP (MVP работает полностью бесплатно, paywall добавляется позже)

## 11. Архитектура и структура проекта

### Паттерн: MVVM

```
MentalMath/
├── App/                    # Точка входа, AppDelegate
├── Models/                 # Доменные модели
│   ├── Problem.swift       # Задача (операнды, операция, ответ, сложность)
│   ├── Session.swift       # Сессия тренировки
│   ├── UserProfile.swift   # Профиль пользователя (уровни по областям)
│   └── SkillLevel.swift    # Уровень навыка по операции/диапазону
├── Domain/                 # Бизнес-логика
│   ├── ProblemGenerator/   # Протокол + реализации генераторов задач
│   ├── DiagnosticEngine/   # Логика диагностики уровня
│   ├── AdaptiveEngine/     # Адаптивная подстройка сложности
│   └── ScoreCalculator/    # Подсчёт результатов и статистики
├── ViewModels/             # Presentation layer (MVVM)
├── Views/                  # SwiftUI views
│   ├── Onboarding/         # Экраны онбординга
│   ├── Training/           # Экран тренировки
│   ├── Statistics/         # Экран статистики
│   ├── Settings/           # Экран настроек
│   ├── Paywall/            # Экран покупки Pro
│   └── Components/         # Переиспользуемые UI-компоненты
├── Services/
│   ├── Storage/            # Абстракция хранения (протокол + реализация)
│   ├── IAP/                # In-app purchases (StoreKit 2)
│   ├── Notifications/      # Push-уведомления
│   └── HapticService/      # Вибро-обратная связь
└── Resources/              # Assets, локализация
```

### Ключевые принципы

- **Протоколы** для генераторов задач и режимов тренировки — расширяемость без модификации существующего кода
- **Абстрактный слой хранения:** протокол `StorageService`, реализация на SwiftData (или UserDefaults для простых данных). Можно заменить без изменения бизнес-логики
- **Комментарии** к нетривиальной логике: генерация задач, адаптивность, расчёт статистики

**Приоритет:** MVP (структура, модели, domain-слой, базовые views), Post-MVP (IAP, уведомления, paywall)

## 12. Генератор задач

### Что делает
Создаёт математические задачи на основе профиля пользователя и выбранных настроек.

### Зачем
Адаптивная генерация — основа продукта. Без неё приложение не отличается от случайного набора примеров.

### Как работает

**Протокол `ProblemGenerator`:**
- Метод генерации задачи принимает `UserProfile` и `Settings`
- Возвращает `Problem` — структуру с операндами, операцией, правильным ответом и уровнем сложности

**Структура задачи (`Problem`):**
- Операнд A, операнд B
- Операция (+, −, ×, ÷)
- Правильный ответ
- Уровень сложности (диапазон чисел)

**Правила генерации:**
- Для деления: только задачи с целым ответом (без остатка)
- Для вычитания: результат может быть отрицательным (настраиваемо)
- Диапазон чисел определяется уровнем сложности

**Адаптивность:**
- Чаще генерирует задачи из слабых областей пользователя
- Реже — из сильных (для поддержания навыка)
- Распределение: ~70% слабые области, ~30% сильные (настраиваемо)

**Расширяемость:**
- Архитектура через протоколы позволяет добавить:
  - Цепочки операций (например, `12 + 5 × 3`)
  - Пропущенные числа (`? + 7 = 15`)
  - Обратные задачи (`какое число при умножении на 6 даёт 42?`)

**Приоритет:** MVP (базовый генератор, 4 операции, адаптивность), Post-MVP (цепочки, пропущенные числа)

## Открытые вопросы

1. **Отрицательные результаты при вычитании:** разрешать ли отрицательные ответы в MVP или ограничить генерацию так, чтобы первый операнд всегда был больше?

2. **Пороги адаптивности:** какие конкретно пороги (% правильных, время ответа) считать «слабой областью»? Нужно определить при реализации DiagnosticEngine.

3. **Спасение стрика:** механика «freeze» (пропустить один день без потери стрика) — включать ли в Pro или оставить бесплатным?
